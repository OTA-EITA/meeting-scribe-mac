# meeting-live（会議の文字起こしをライブで受け取る）

MeetingScribe（Windows 版も同じ形式）のエンジンは `ws://127.0.0.1:8765` で文字起こしを配っている。
リポジトリの `scribe-tail/scribe-tail.mjs` が差分を取り、確定した発言を 1 行ずつ出す。

このファイルはリポジトリの `.claude/skills/meeting-live/SKILL.md` にある。リポジトリの場所（以下 `REPO`）は、このスキルのフォルダから 3 つ上。`~/.claude/skills/` にリンクして使っているときは、リンク先から 3 つ上をたどる（`readlink` で確かめる）。

Monitor は最長 30 分で切れるので、scribe-tail は tmux に置いてファイルへ書かせ、こちらはそのファイルを `tail -F` で読む。張り直しても二重にならない。

## 始める

要るもの: MeetingScribe のアプリ、Node.js 22 以上、tmux（`brew install tmux`）。無ければ本人に入れてもらう。

1. 先に tmux のセッションを確かめる。`tmux has-session -t scribe 2>/dev/null` が成功するなら、もう動いているのでそのログを使う
2. 動いていなければ起こす
   ```bash
   LOG=~/meeting-logs/$(date +%Y%m%d-%H%M).log
   mkdir -p ~/meeting-logs && : > "$LOG" && ln -sf "$LOG" ~/meeting-logs/current.log
   tmux new-session -d -s scribe "node '$REPO/scribe-tail/scribe-tail.mjs' --status --out '$LOG' --minutes ~/meeting-logs/minutes"
   ```
3. Monitor を張る（`timeout_ms: 1800000`、description は `会議の区切り`）。録音中の 1 行ずつは通知しない（ログには全部残る）。通知するのは録音の停止と、エラー・注意だけ
   ```bash
   tail -n 0 -F ~/meeting-logs/current.log | grep --line-buffered -E '^# .*(議事録の写し|録音停止|エラー|注意|起動していません)'
   ```
4. 本人に一言: 「つなぎました。録音を止めるたびに、要約と次に聞くことを出します」。エンジンが起動していなければアプリの起動を頼む

Monitor が切れたら（30 分ごと）、同じコマンドで張り直す。会議が終わるまで続ける。

## 使い方の前提

本人は会議の途中で何度か録音を止める。**止めるたびに、言われなくても分析を返す**。録音中は黙っている。

## 録音が止まったら（`# … 議事録の写し: <path>` が届いたら）

アプリは議事録を暗号化して保存する（`録音停止 保存先:` の `.txt.enc` は読めない）。scribe-tail が同じ中身を平文で `~/meeting-logs/minutes/` に書き出し、`議事録の写し:` で場所を知らせる。

1. `<path>` の議事録の写しを Read する。停止後に録音全体を文字起こしし直した正式なもので、録音中のログより正確。`録音停止` だけ来て `議事録の写し` が来なければ、`current.log` の直近の録音中の行で代わりにする
2. この会議でそれまでに止めた回の写しも読む（`current.log` の過去の `議事録の写し:` の行にパスがある）。話の流れを踏まえて、前の回で出たことは繰り返さない
3. 次の形で、短く返す。会議中にちらっと見て使えるように、各項目 1〜3 行、全体で画面 1 枚に収める
   ```
   **ここまでの要約**（この回で新しく出たこと）
   - …
   **相手の要望・条件・数字**
   - 金額・日付・期限・人数などは原文の数字で
   **次に聞くべきこと**（優先順に 3 つまで）
   1. 相手が言ったのにあいまいなまま残っていること
   2. こちらの判断に要るのにまだ出ていないこと
   3. 相手の迷い・懸念を解くための質問
   ```
4. PushNotification で「次に聞くこと」の 1 つ目だけ送る（本人が画面を見ていないことがあるため）
5. 本人が最初に会議の目的や見てほしい点（「条件を詰めたい」「懸念を引き出したい」など）を言っていれば、それに沿って「次に聞くべきこと」を選ぶ

### 気をつけること
- 文字起こしには誤認識がある。前後から読める誤り（「三つ森」→見積もり）は直して書いてよいが、数字や固有名詞があやしいときは「（要確認）」を付ける
- `[自分]` と `[相手…]` のラベルはときどき入れ替わる。発言の中身から、どちらの発言か判断する
- 相手が言っていないことを要約に書かない

## 終わる

「会議終わり」「止めて」と言われたら:
1. Monitor を TaskStop で止める
2. `tmux kill-session -t scribe`
3. 頼まれていれば、保存先の議事録（なければ `current.log`）から要点・決まったこと・宿題をまとめる

## 注意
- 会議の中身は社外秘のことがある。ログや議事録の写しを外部サービスに送らない、リポジトリにコミットしない
- 文字起こしは誤認識がある（固有名詞・数字）。断言する前に本人に確かめる
