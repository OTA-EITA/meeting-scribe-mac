# MeetingScribe

ローカルの Whisper (WhisperKit) だけで動く、macOS ネイティブの会議文字起こしアプリです。音声データはすべて端末内で処理され、外部に送信されません。

## できること

- マイク入力 + システム出力音声(スピーカー/イヤホンから鳴る音、Google Meet 等の相手の声を含む)を合成したリアルタイム文字起こし
- 話者分離(誰が話したかを `[話者1]` のようにラベル付け)
- 録音停止のたびに議事録として指定フォルダへ自動でテキスト保存(保存先はアプリ内で変更可能)。各行に録音開始からの経過時間 `[00:12:34]` が付き、同じ名前の Markdown (.md) も保存できる
- 録音停止後、「相手1」「相手2」を実際の名前に付け替えられる(画面と保存済みの議事録の両方に反映)
- 「ご視聴ありがとうございました」「(音楽)」のような Whisper の定型の誤認識を自動で取り除く
- 文字起こしモデル(small / medium / large-v3 turbo)をアプリ内で切り替えられる
- 会議アプリの上に重ねて表示できる、半透明・スクロール式の字幕オーバーレイ(発話中の部分は太字)
- メニューバー常駐。メインウィンドウを閉じてもバックグラウンドで動作を続けられる

## 技術選定

- **Swift / SwiftUI**: macOS ネイティブアプリとして実装。
- **[WhisperKit](https://github.com/argmaxinc/WhisperKit)**: Apple Silicon 向けに CoreML 最適化された、純 Swift の音声認識ライブラリ。`whisper.cpp` の手動ビルドが不要で、SPM 依存として組み込める。文字起こしには `small` モデルを使用(`base` は日本語での誤認識・幻聴が多かったため変更)。リアルタイム処理には WhisperKit 標準の `AudioStreamTranscriber` を使用。
- **[SpeakerKit](https://github.com/argmaxinc/WhisperKit)** (WhisperKit と同じリポジトリに同梱): pyannote ベースのオンデバイス話者分離。録音停止後にまとめて解析し、確定した文字起こしセグメントへ話者ラベルを付与する。
- **Core Audio のプロセスタップ**: システム出力音声のキャプチャに使用。マイクだけでは、イヤホン使用時に会議相手の声を拾えないため導入した。音はイヤホンへ送られる前に取る。以前は ScreenCaptureKit を使っていたが、「画面とシステムオーディオの収録」の許可が要り、macOS 15 以降はその許可を定期的に確かめ直してくるため切り替えた。プロセスタップは「システムオーディオ録音のみ」の許可で済み、一度許可すれば聞き直されない。macOS 14.2 より前では ScreenCaptureKit のまま動く。
- **ローカル WebSocket (`Network.framework` のサーバー側 + 自前実装の生ソケットクライアント)**: 録音・文字起こしを行うエンジン(`TranscriptionServer`)と、メインウィンドウ・字幕オーバーレイという複数の UI 表示先を疎結合にするための内部通信路として採用。詳細は後述の既知の制限を参照。

## ビルド・実行方法

```bash
git clone <this repo>
cd meeting-scribe-mac

# 初回のみ: ローカルのコード署名証明書を作成(下記「署名について」を参照)
./setup-dev-signing-cert.sh

# ビルド + .app バンドルとして生成
./build-app.sh

# 起動
open .build/MeetingScribe.app
```

普段使うときは、release でビルドして `/Applications` に入れる。

```bash
./install-app.sh
```

入れたあとの最初の起動で、マイクとシステム音声の許可のダイアログが続けて出るので、どちらも許可する。録音を始めた瞬間にダイアログが出て会議の冒頭を取り逃がさないよう、許可は起動時にまとめて求める。一度許可すれば、入れ直しても聞かれない。

### テストの実行

```bash
./run-tests.sh
```

Xcode 本体が無く Command Line Tools だけの環境でも動くよう、テストは XCTest ではなく Swift Testing で書いている。`run-tests.sh` は Command Line Tools に同梱された Swift Testing の場所を `swift test` に渡す。

初回起動時、マイクとシステム音声の録音の許可ダイアログが出るので許可してください。WhisperKit の `small` モデルと SpeakerKit の話者分離モデルは初回起動時に自動ダウンロードされます(合計 500MB 程度、数分かかることがあります)。

### 署名について(重要)

`swift build` だけで作られる実行ファイルは ad-hoc 署名(`codesign -s -`)されますが、これは**再ビルドのたびに署名ハッシュが変わり**ます。マイク権限は再ビルド後も維持されますが、**画面/システム音声キャプチャの権限は再ビルドのたびに失われ、しかも自動では再度ダイアログが出ません**(実機検証で判明した macOS の挙動)。

これを避けるため `setup-dev-signing-cert.sh` でローカルの自己署名コード署名証明書(`MeetingScribe Dev`)をログインキーチェーンに作成し、`build-app.sh` はこの証明書でアプリ全体に署名します。証明書の秘密鍵は再ビルドしても変わらないため、一度権限を許可すれば以後の再ビルドでも維持されます。

証明書の秘密鍵は `codesign` からしか使えないようにしている。どのアプリからでも使える設定にすると、他のプログラムが同じ証明書で自分に署名し、このアプリに与えたマイクやシステム音声の許可を横取りできてしまうため。以前の版のスクリプトで証明書を作った場合はこの設定になっていないので、次のコマンドで作り直す(途中で Mac のパスワードを2回求められる。作り直した後は画面/システム音声キャプチャの許可を一度与え直す)。

```bash
./setup-dev-signing-cert.sh --recreate
./build-app.sh
```

万一システム音声キャプチャの権限がおかしくなった場合は、以下を試してください。

```bash
tccutil reset AudioCapture local.meetingscribe
```

その後アプリを再起動すると、許可ダイアログが再度表示されます。

## 使い方

1. メインウィンドウで「マイク (自分の声)」と「相手の声を取る出力先」を確かめる。既定は Mac の設定に従い、いま使っているデバイス名が出る。イヤホンで聞くときは、出力先をそのイヤホンにする。イヤホンを抜き差ししたら「一覧を更新」を押す
2. 「録音を開始」を押す
3. 会議を行う(マイクの声とシステム出力音声の両方が文字起こし対象)
4. 「停止する」を押すと、録音全体を文字起こしし直し、話者分離を実行したうえで結果が表示され、指定フォルダに議事録として自動保存される。録音中の文字起こしは処理が遅れると一部を飛ばすことがあるため、保存する議事録は停止後に作り直している。90 秒の録音で 15 秒ほどかかる
5. 会議の途中で何度止めてもよい。止めるたびに別の議事録として保存される
6. 必要なら「字幕オーバーレイも表示」で、会議アプリの上に字幕を重ねて表示できる(ドラッグで位置調整、スライダーで濃さ調整が可能)
7. メインウィンドウを閉じてもアプリはメニューバーに常駐し続ける。メニューバーのアイコンから録音の開始/停止、オーバーレイの表示切り替え、終了ができる

## Chrome 拡張機能

`chrome-extension/` は、Chrome のサイドパネルから字幕を見て録音を開始・停止するための拡張機能です。文字起こしは Mac アプリが行い、拡張機能はローカルの WebSocket (`ws://127.0.0.1:8765`) でつなぐ画面だけを受け持ちます。使うときは Mac アプリを起動しておいてください。Windows 版のアプリも同じ約束事で待ち受けるので、Windows でもこの拡張機能をそのまま使えます。

1. Chrome で `chrome://extensions` を開き、右上の「デベロッパー モード」をオンにする
2. 「パッケージ化されていない拡張機能を読み込む」で `chrome-extension` フォルダを選ぶ
3. ツールバーの MeetingScribe のアイコンを押すと、サイドパネルが開く

ブラウザの WebSocket には CORS の制限がかからないため、エンジンは接続時の Origin ヘッダーを確かめ、この拡張機能以外のウェブサイトからの接続を断ります。拡張機能の ID は `manifest.json` の `key` で `pjkgdgbmgcoooolfkjjgkinidnccojhj` に固定しており、`OriginPolicy.swift` の値と一致させています。

拡張機能の単体テストは次のコマンドで実行します。

```bash
cd chrome-extension && npm test
```

## 文字起こしを他のツールへ流す (scribe-tail)

`scribe-tail/` は、エンジンのローカル WebSocket につなぎ、確定した文字起こしを 1 行ずつ標準出力へ流す小さな CLI です。`tail -f` と同じ感覚で、会議の内容をその場で他のツールに渡せます。Node.js 22 以上だけで動き、依存パッケージはありません。Windows 版のアプリにもそのままつなげます。

```bash
node scribe-tail/scribe-tail.mjs --status
# 14:02:11 [自分] では始めます
# 14:02:15 [相手1] よろしくお願いします
```

- エンジンは確定した文字起こしを毎回最初から送ってくるので、前回との差分だけを出す。同じ話者が話し続けて伸びている行は、話が途切れたとき(既定 2.5 秒、`--idle-ms` で変更)か 120 文字ごとに出す
- 前に出した行が書き換わったとき(話者ラベルの付け替えなど)は、行頭に `(訂正)` を付けてその行から出し直す
- 停止後に送り直される全文は、録音中に流し終えていれば出さない。Windows 版のように停止後にまとめて文字起こしするエンジンでは、その全文を流す
- `--out meeting.log` で同じ内容をファイルにも追記する。`--status` で録音の開始・停止・保存先を行頭 `#` で出す
- `--others-only` で相手の発言だけを出す。録音中の相手のラベルは `相手` `相手1` … か `不明` で始まるので、それ以外のラベルの行を出さない
- 既定では確定した部分だけを出す。最後の数かたまりは後ろに続きの音声が来るまで確定しないので、短く話して黙るとしばらく出てこない。`--fast` を付けると、エンジンが送る確定前の部分(`liveText`)も話が途切れたときに出す。すぐ出る代わりに、言い直しで `(訂正)` が増える
- アプリが起動していなければ、起動するまで 2 秒おきにつなぎ直す

テストは次のコマンドで実行します。

```bash
cd scribe-tail && npm test
```

## 既知の制限・注意点

- **企業のセキュリティソフト(VPN/EDR)がある環境では、ローカルの WebSocket 通信(ループバック)が中断されることがあります。** 本プロジェクトの開発機では FortiClient の VPN 用ネットワーク拡張が `NWConnection`(Apple の Network.framework)経由のループバック通信を中断させる現象が確認されたため、UI 側のクライアントは Network.framework を使わず、生の BSD ソケットで実装した WebSocket クライアント(`RawWebSocketClient.swift`)を使っている。同様の環境では他の内部通信にも影響が出る可能性がある。
- 文字起こし精度は既定の "small" モデル相応。medium や large-v3 turbo に切り替えると精度は上がるが、初回に 1.5GB 前後のダウンロードがあり、処理も重くなる。
- 定型の誤認識は既知の文言と括弧書きの注記だけを取り除く。それ以外の誤認識は残る。
- エンジンのローカル WebSocket は 127.0.0.1 だけで待ち受ける。同じネットワークの他の端末からは接続できない。
- 話者分離は録音停止後にまとめて実行する方式(録音全体を再解析するため、長い録音では数秒〜数十秒かかる)。リアルタイムでの話者ラベル付けには対応していない。
- Windows 版は本プロジェクトの対象外(別途 Electron で検討予定)。
